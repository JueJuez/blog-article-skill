# weread 公众号代理 · 认知与防踩坑手册

> 目的：把我们对 `weread.111965.xyz` 免费代理的**边界、运作方式、坑**一次性沉淀清楚，
> 让任何新会话/新 Agent 不再把同样的坑踩一遍，并能据此**更好地利用代理**（而不是被它骗）。
> 本文件是事实记录，**磁盘证据优先于任何推断**。
> 入口代码：`monitors/wechat.py` / `monitors/run.py` / `monitors/backfill.py`。
>
> **稳定边界（2026-08-19 确定）**：weread 免费代理可稳定返回约 **最近 30~35 天** 的文章。
> 哥飞 23 篇 raw 全部落在 2026-07-24~08-19（27 天内）；更老的历史返回乱序/伪造时间戳，
> 极不可靠。因此代码默认 `since = 今天 - 35 天`，超过此边界**不再补**。

---

## 1. 代理是什么

- 一个**免费的、共享的**微信公众号文章转发/抓取服务器（`weread.111965.xyz`）。
- 给公众号 `mp_id` / `share_url` → 返回**文章列表（仅元数据：标题、publishTime、id、url）**；
  正文需另用 `fetch_web_content(mp.weixin.qq.com/s/<aid>)` 直连抓取（可达 3k–11k 字）。
- **非官方、无 SLA、行为高度不稳定**——所有"边界"都来自实测，不是文档约定。

## 2. 认证 / token

- 凭据存 `monitors/.wechat_auth.json`（`token` + `vid`），由扫码登录签发。
- **寿命 ≈ 2 小时**（实测：21:44 扫 → 次日 00:34 仍有效，约 2h50m；02:34 必过期）。
- 登录：生成 `monitors/login_qr.png` + 起 poll daemon（`monitors/.poll_daemon.*`）轮询扫码结果写回 auth。
- `is_token_valid` **偏"失效"**：代理 500 / 异常等无法确认有效时，判失效触发重登，
  根绝"过期+500 静默失败"。（2026-08-19 修，提交 3763d85）
- 长任务必配自动弹码续期，否则 token 过期后**静默空转**。

## 3. 代理行为边界（核心，反复踩坑区）

| 行为 | 实测表现 | 后果 / 对策 |
|---|---|---|
| **乱序分片** | 单次 `discover` 只返回**一个随机分片**，不是从新到老的连续历史。翻页也乱：`(1,空)(2,空)(3,50篇更老)(4,空)(5,50篇)(6-15,空)`。 | 单轮抓不全；**稳定窗口内**问题小，深层严重。`iter_articles` 容错：开头连续 5 页空快退，拿到数据后连续 3 页空才停（仅用于近月补抓）。 |
| **空窗** | 间歇返回 200 空页；代理冷启动瞬间也空。 | `cmd_backfill` 短退避重试（最多 5 次、8→30s）抓住恢复窗口；超过稳定边界不再追。 |
| **401 / 500 翻转** | token 失效→401；代理抖动→500/异常。 | **401 必须上抛**触发二维码重登；500/异常按"失效"处理（偏保守，避免静默失败）。 |
| **publishTime 元数据不可信** ⚠️ | 对 **2026 年**的哥飞账号，代理竟返回伪造的 **2024-08-16** 时间戳。 | **绝不用 publishTime 做完成判定或深度推断**。窗口过滤仍用它，但"抓到哪"只看**磁盘最老发布日期**。 |
| **高频抖动** | 8s 内 `0→50→0` 翻转。 | 单次返回 0 不代表抓完；短退避重试，不追求深历史 exhaustive。 |
| **单篇正文壳** | 个别文章代理返回空页，正文只有"原文链接：https://mp.weixin.qq.com/..."壳。 | `apply_summaries` 同次运行内退避重试 3 次（6/12/18s），命中即总结；耗尽降级跨轮 `pending_refetch`。 |

## 4. 深度与稳定边界（探针证据，**非推断**）

### 4.1 稳定边界（默认补抓范围）
- 磁盘证据：哥飞 **23 篇 raw 全部落在 2026-07-24 ~ 2026-08-19**，即 **27 天内**。
- 日常监控最大窗口 `WECHAT_MAX_WINDOW_DAYS=30` 也落在同一区间。
- **结论**：weread 免费代理可稳定返回约 **最近 30~35 天** 的文章。代码默认 `WECHAT_BACKFILL_DAYS=35`，超过此边界不补。

### 4.2 探针实测的"可达"深度（仅供参考，不用于生产）
> 用有效 token 翻 1~15 页、按 id 去重统计的最老发布日期与篇数：
> - **哥飞**：去重 **100 篇**，最老 **2025-04-15**。
> - **生财有术**：去重 **214 篇**，最老 **2024-12-17**（且跳过了 2025-05~2026-03 整段）。
>
> ⚠️ 这是**代理"可达"深度**，不是"已抓到"深度；乱序 + 空窗导致拼全极不可靠。
> 生产环境**以 4.1 的稳定边界为界**，不再追深历史。

## 5. 完成判定的三次假完成（血泪史，务必记住）

回溯的 `backfill_done` 标记**三次**因代理特性误判，每次都让"以为抓完了"实则深层没抓：

1. **v1 · 0 新 / 小分片 → 假完成**：旧逻辑在"单轮乱序分片 0 新 或 未见数≤batch"时标 done。
   乱序下第一次常撞**近期分片**（已被每日监控 seen）→ `new==0` → 立刻"完成"。**已删除该触发。**
2. **v2 · reached_since 伪造元数据 → 假完成（2026-08-19 再现）**：改用 `oldest_raw=min(publishTime) < since` 判"越过边界"。
   但代理对 2026 账号返回伪造的 2024-08-16 时间戳 → `oldest_raw < since` 恒成立 → 又标 done；
   而该伪造老文章被 `since` 过滤剔除、从未落盘，深层(2025-04)照样没抓。**已彻底移除 discover 内所有 done 标记。**
3. **seen 计数 ≠ 代理深度**：`seen` 是累计去重 id 集合（含每日监控+壳/空页），**不是**单次可达深度。
   （例：哥飞 seen=108 只代表累计见过 108 个 id，深层可能根本没翻到。）

**唯一诚实的"抓到哪"信号**：**磁盘最老发布日期**。`state.backfill[...].reason`、`seen` 计数、`publishTime` 全部不可信。
深历史抓取已放弃，因此也不再需要"连续 N 轮 0 落盘"驱动——稳定窗口内跑一次即算完成。

## 6. 什么能可靠做 / 什么不能

✅ **能可靠做**
- 每日监控（最近 2 天窗口）：稳定，日常主用。
- 补最近 **30~35 天** 的漏抓文章：命中率高、耗时可控。
- token 失效自动弹码续期。
- 单篇正文壳退避补抓。

❌ **不能可靠做**
- **深挖历史"抓全"**（超过 35 天）：乱序→单轮只一个分片；伪造时间戳→假完成；空窗→耗时巨大。
  2025 年深历史预期耗时以小时计、命中率低、且仍可能漏段——**已决定不追**。
- **用 seen 计数 / backfill reason / publishTime 推断"抓到哪 / 代理多深"**：全部不可信。

## 7. 操作铁律（新会话直接照做，别再推理）

1. **补抓默认只跑最近 35 天**（`WECHAT_BACKFILL_DAYS`），超过此边界不补；如需深挖必须显式 `--since` 并自行承担漏段风险。
2. **磁盘最老发布日期**才是"抓到哪"的真相；`state.backfill[...].reason`、`seen` 计数、`publishTime` 都不可信。
3. `wechat.py` 的 `discover` 内**不再写 `backfill_done`**（代码已强制）；队列 job 跑一次即完成，不 exhaustive。
4. 代理空窗时短退避重试（最多 5 次），超过稳定边界不再恋战。
5. 长任务**必配自动弹码续期**，否则 token 过期静默空转。
6. 不要从 `seen` 计数推断代理深度；要深度用 `verify_proxy_depth.py` 探针实测，但生产不依赖深历史。

- 生财：0 篇落盘（代理空窗+乱序），深层(2024-12)**未抓**；重置为 `stopped_zero_captured_unreliable_proxy`。

## 9. 代理死亡 + 本机劫持（2026-09-18 确诊 · 公众号源已停用）

用户报「微信代理连续半个月不可用」。实测为**两层故障叠加**：

### 9.1 本机 DNS 劫持（请求根本没出网）
- `socket.gethostbyname('weread.111965.xyz')` → **127.0.0.1**；但 `C:\Windows\System32\drivers\etc\hosts`
  里**没有**这一行（68 行劫持全是 Steam++ 的 steam/twitch/ubisoft）。
- `0.0.0.0:443` 被 **`Steam++.Accelerator.exe`**（Watt Toolkit 加速服务）监听，对本站返回自签证书
  `issuer=CN=SteamTools Certificate, O=BeyondDimension` → requests 抛 `CERTIFICATE_VERIFY_FAILED`。
- 后果：`is_proxy_reachable()` 失败 → 代码按设计判定「代理不可达、过期判定不可信」→ **不弹码、直接跳过**，
  表现为 `article=0 / status=ok` 的**静默零结果**，连日志都只有一行 warning。

### 9.2 源站真的 502（绕过劫持仍不可用）
- 绕过本地解析直连真 IP：`curl --resolve weread.111965.xyz:443:172.67.173.210`（真 IP 由公共 DNS
  223.5.5.5 / 119.29.29.29 查得，Cloudflare `172.67.173.210` / `104.21.47.228`）。
- 证书校验**通过**，但 `/`、`/api/v2/login/platform`、`/api/v2/platform/mps/*/articles` **全部 502**
  （Cloudflare `error code: 502`），两个 IP 皆然 → **CF 正常、回源失败 = 后端源站已死**。
- 死亡时间：`.wechat_auth.json` mtime 与 `state.json` 四个 wechat 源 `last_check` 全部冻结在
  **2026-08-28 18:23**（JWT iat 08-28 18:19）→ 实际 **21 天**，比用户感知的「半个月」更早。

### 9.3 处置（2026-09-18 用户拍板：暂时搁置）
- 新增**总开关** `WECHAT_SOURCE_ENABLED`（`monitors/run.py`，**默认 0 = 停用**）：停用后不探代理、
  不弹二维码、不重试，`--backfill` 直接拒绝执行；B站 / scys 七域照常。
  源站恢复后 `WECHAT_SOURCE_ENABLED=1 python monitors/run.py --mode auto --apply` 即复开。
- **只停「列表发现」**：手工贴 `mp.weixin.qq.com/s/<aid>` 链接落盘不受影响（正文直连仍可用）。
- 若将来换源：改 `WEREAD_PLATFORM_URL`（`monitors/wechat.py:25` 已支持覆盖）+ 置 `WECHAT_SOURCE_ENABLED=1`。
- 未处理：本机 DNS 劫持（需退出 Steam++ 或关其网络加速）。**源站活着之前不急着处理**，
  否则恢复了也还是连不上——两个都得修才有用。

### 9.4 教训
- ⚠️ 「代理不可达」被设计成静默跳过，多轮零结果**无任何告警**，故障能被掩盖三周。
  日后若要复开，应补「连续 N 轮公众号 0 结果」的显式告警（本次未做）。
