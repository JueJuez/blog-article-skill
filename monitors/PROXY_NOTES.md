# weread 公众号代理 · 认知与防踩坑手册

> 目的：把我们对 `weread.111965.xyz` 免费代理的**边界、运作方式、坑**一次性沉淀清楚，
> 让任何新会话/新 Agent 不再把同样的坑踩一遍，并能据此**更好地利用代理**（而不是被它骗）。
> 本文件是事实记录，**磁盘证据优先于任何推断**。
> 入口代码：`monitors/wechat.py` / `monitors/run.py` / `monitors/backfill_deep.py`。

---

## 1. 代理是什么

- 一个**免费的、共享的**微信公众号文章转发/抓取服务器（`weread.111965.xyz`）。
- 给公众号 `mp_id` / `share_url` → 返回**文章列表（仅元数据：标题、publishTime、id、url）**；
  正文需另用 `fetch_web_content(mp.weixin.qq.com/s/<aid>)` 直连抓取（可达 3k–11k 字）。
- **非官方、无 SLA、行为高度不稳定**——所有"边界"都来自实测，不是文档约定。

## 2. 认证 / token

- 凭据存 `monitors/.wechat_auth.json`（`token` + `vid`），由扫码登录签发。
- **寿命 ≈ 2 小时**（实测：21:44 扫 → 次日 00:34 仍有效，约 2h50m；02:34 必过期）。
- 登录：生成 `monitors/login_qr.png` + 起 poll daemon（`monitors/.poll_daemon.*`）轮询扫码结果写回 auth。
- `is_token_valid` **偏"失效"**：代理 500 / 异常等无法确认有效时，判失效触发重登，
  根绝"过期+500 静默失败"。（2026-08-19 修，提交 3763d85）
- 长任务必配自动弹码续期，否则 token 过期后**静默空转**。

## 3. 代理行为边界（核心，反复踩坑区）

| 行为 | 实测表现 | 后果 / 对策 |
|---|---|---|
| **乱序分片** | 单次 `discover` 只返回**一个随机分片**，不是从新到老的连续历史。翻页也乱：`(1,空)(2,空)(3,50篇更老)(4,空)(5,50篇)(6-15,空)`。 | 单轮抓不全；深层历史需**多轮累积 + seen 去重**。`iter_articles` 已容错：开头连续 10 页空快退（防空窗盲等），拿到数据后连续 6 页空才停。 |
| **空窗** | 间歇返回 200 空页；代理冷启动瞬间也空。 | `cmd_backfill` 退避重试（最多 20 次、8→60s 递增）抓住恢复窗口；智能探测优先（有数据才抓）比盲目重试高效。 |
| **401 / 500 翻转** | token 失效→401；代理抖动→500/异常。 | **401 必须上抛**触发二维码重登（旧版吞 401→永远不弹码→静默空转，已修）；500/异常按"失效"处理（偏保守，避免静默失败）。 |
| **publishTime 元数据不可信** ⚠️ | 对 **2026 年**的哥飞账号，代理竟返回伪造的 **2024-08-16** 时间戳。 | **绝不用 publishTime 做完成判定或深度推断**——它会被伪造，导致假完成（详见 §5）。时间窗口/过滤仍用它，但完成判定与"抓到哪"只看**磁盘最老发布日期**。 |
| **高频抖动** | 8s 内 `0→50→0` 翻转。 | 单次返回 0 不代表抓完；退避重试。 |
| **单篇正文壳** | 个别文章代理返回空页，正文只有"原文链接：https://mp.weixin.qq.com/..."壳。 | `apply_summaries` 同次运行内退避重试 3 次（6/12/18s），命中即总结；耗尽降级跨轮 `pending_refetch`。 |

## 4. 实测可达深度（探针证据，**非推断**）

> 用有效 token 翻 1~15 页、按 id 去重统计的最老发布日期与篇数：
> - **哥飞**：去重 **100 篇**，最老 **2025-04-15**，最新 2026-01-19。
> - **生财有术**：去重 **214 篇**，最老 **2024-12-17**，最新 2026-06-09（**跳过了 2025-05~2026-03 整段**——这次没拿到）。
>
> ⚠️ 这是**代理"可达"深度**，不是"已抓到"深度。乱序下单次 run 只拿到一个分片，
> 拼全需多轮。且上述为某次探针结果，代理随时变，不可当恒定上限。

## 5. 完成判定的三次假完成（血泪史，务必记住）

回溯的 `backfill_done` 标记**三次**因代理特性误判，每次都让"以为抓完了"实则深层没抓：

1. **v1 · 0 新 / 小分片 → 假完成**：旧逻辑在"单轮乱序分片 0 新 或 未见数≤batch"时标 done。
   乱序下第一次常撞**近期分片**（已被每日监控 seen）→ `new==0` → 立刻"完成"。**已删除该触发。**
2. **v2 · reached_since 伪造元数据 → 假完成（2026-08-19 再现）**：改用 `oldest_raw=min(publishTime) < since` 判"越过边界"。
   但代理对 2026 账号返回伪造的 2024-08-16 时间戳 → `oldest_raw < since` 恒成立 → 又标 done；
   而该伪造老文章被 `since` 过滤剔除、从未落盘，深层(2025-04)照样没抓。**已彻底移除 discover 内所有 done 标记。**
3. **seen 计数 ≠ 代理深度**：`seen` 是累计去重 id 集合（含每日监控+壳/空页），**不是**单次可达深度。
   （例：哥飞 seen=108 只代表累计见过 108 个 id，深层可能根本没翻到。）

**唯一诚实的完成信号**：外层驱动 `monitors/backfill_deep.py` 的**「连续 N 轮 0 落盘」(EMPTY_THRESHOLD=12)**。
它基于"实际落盘数"，不依赖任何代理元数据。**磁盘最老发布日期 = 真相。**

## 6. 什么能可靠做 / 什么不能

✅ **能可靠做**
- 每日监控（最近 2 天窗口）：稳定，日常主用。
- 单次**近期**抓取（2026 文章）：命中率高。
- token 失效自动弹码续期。
- 单篇正文壳退避补抓。

❌ **不能可靠做**
- **深挖历史"抓全"**：乱序→单轮只一个分片；伪造时间戳→假完成；空窗→耗时巨大。
  想拼全 2025 深历史，预期耗时以小时计、命中率低、且仍可能漏段。
- **用 seen 计数 / backfill reason / publishTime 推断"抓到哪 / 代理多深"**：全部不可信。

## 7. 操作铁律（新会话直接照做，别再推理）

1. 回溯完成判定**只认驱动连续 0 新**，`discover` 不再写 done（代码已强制）。
2. **磁盘最老发布日期**才是"抓到哪"的真相；`state.backfill[...].reason`、`seen` 计数、`publishTime` 都不可信。
3. 想抓深历史：预期耗时巨大、命中率低；**优先抓近期(2026)，深历史(2025)性价比低、可主动放弃**。
4. 代理恢复窗口随机 → **智能探测优先**（有数据才抓）比盲目重试高效。
5. 长任务**必配自动弹码续期**，否则 token 过期静默空转。
6. 不要从 `seen` 计数推断代理深度；要深度用 `verify_proxy_depth.py` 探针实测。
