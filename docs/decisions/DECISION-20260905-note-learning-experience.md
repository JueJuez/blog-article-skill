# DECISION-20260905-note-learning-experience 阅读体验与学习效率增强包

**日期**：2026-09-05 ｜ **状态**：已实施（含 Mermaid 三改 + 门禁目的审计第二批）｜ **测试**：`tests/test_template_learning_20260905.py` + `test_prompt_hygiene.py` + `test_gate_purpose_audit_20260905.py` ｜ 全量 384 过

## 决策
按学习金字塔「被动 < 主动」定性排序（百分比数据缺科学依据，不采用）补齐模板学习层：
- **看**（视觉结构）：Mermaid 图 4 模板（case 决策链图 / opinion 论证结构图 / reading 全书结构图 / dissection 打法链路图）+ `MERMAID_RULE` 十八节（structured / general 内联，深度技术文主落点此前无图规则）；金句 `[!quote]`（key_points / reading）+ 风险 `[!warning]`（reading / dissection）。
- **测**（检索练习）：自测三问 `[!question]-` 折叠块——structured 内联第十六节 + reading / case 固定条目；每题须能在原文找到依据，无可考内容整块省略。
- **用**（行动转化）：可行动项从 `-` 无序列表升级 `` `- [ ]` `` 复选框（key_points / interview / reading），Obsidian 可勾选。
- **讲**（费曼，金字塔顶）：`FEYNMAN_RULE` 第十七节 + reading / case 条目——讲给外行听，须含自己的类比，主动指出 1 处讲不圆处。
- **结论先行**：structured / UNIVERSAL_RULES 双覆盖「断言式」结论小标题（如「X 导致 Y」而非话题词）。

## 机制
- TDD：RED（35 failed）→ 21 处编辑 `prompts/templates.py`（常量 `SELF_QUIZ_RULE` / `FEYNMAN_RULE` / `MERMAID_RULE` 拼入 CONTENT_SUMMARY_PROMPT 尾部，其余 7 模板走 UNIVERSAL_RULES 拼接 + 模板内条目）→ GREEN（372 passed）。
- 字数基线同步上调（容纳学习块）：case 800～1500→900～1800、reading 1000～2000→1000～2200（`prompts/verifier.py:NOTE_WORD_LIMITS` 同步，防漂移门禁拦截后修正）。
- **Mermaid 三改（用户三轮纠偏定调，目的驱动）**：一改废除「全文最多 1 张」数量门（深度技术文多张正常）→ 二改试设机械质量门被否 → 三改定调：图只有一个目的=帮读者更好地学习理解（外化非线性结构、降低理解成本），唯一约束=不能滥用（凑版面 / 为线性罗列或纯并列强画 / 段落原样搬进节点 / 同一结构关系重复画），张数不设上限、由内容结构复杂度自然决定。
- 所有学习块「按需 + 不凑数」，阅读类（reading/自测/费曼）额外带触发条件（纯文学省自测、无可讲机制省费曼），防模板膨胀。
- **工程教训**：同一文件多条 SearchReplace 并行会互相覆盖（diff 报成功但落盘丢失 9 处），必须逐条串行 + 哨兵 grep 全量审计。

## 第二批 · 门禁目的审计（同日）
把 Mermaid 三改的「目的驱动」推广到全部门禁：每类总结有自己的目的（北极星），硬数字只能作典型区间提示，必须带「以真实数量为准 / 无则省略」逃生口——数量是结果不是规定。修正 5 处一刀切：opinion 论据拆解（条数由真实论据决定，1 条写 1 条）、opinion 正反双方（单面文反对方标「（笔记者推断）」，无依据整块省略，不硬造对立面）、roundup 选购建议（改「若原文有」+ 条数以原文为准）、reading 主题块（3～6 改典型区间，不硬拆不硬并）、思维模型自检「全不适用」（6 条理由改为写作时核验 + 正文落一行结论，读者要洞察不要审计日志；`QUALITY_GATE_SELFCHECK` ① 口径联动对齐）。保留的硬门禁（字数软硬区间 / H1 唯一 / 来源链接卫生 / 禁目录式复述 / 禁凑数）经审计均服务目的，不动。已知缺口：会议纪要无对应类型（分类器会误路由），按 YAGNI 暂不新增，出现真实需求再补模板 + 分类信号。

## 门禁 / 机械化的定位（2026-09-06 补记）
Agent 稳定的是搜集与统计，不稳定的是内容处理；机械化的目的是**用确定性补不稳定性**——门禁是验收器不是生成器：只机械验收「形态」（固定格式落盘：标题 / 链接 / 字数 / 结构合规），不机械约束「思想」（洞察 / 取舍 / 条数）。思想目标塞进机械门禁必然退化成数字游戏（凑条数、硬造反对方），上批修正的 5 处即此退化。加新门禁三问：可机械验证？管形态不管思想？机器拦得住？三者皆否，只进 prompt（模板 / 透镜）或 AI 审核员，不进机械层。
