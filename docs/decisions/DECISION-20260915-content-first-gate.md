# DECISION-20260915 门禁从「字数比例带」改为「内容判据」（内容完整优先）

**状态**：已定方向，待离线审计定阈值后实施
**前序**：`DECISION-20260905-mechanical-verifier.md`（引入机械门禁）→ `DECISION-20260913-gate-source-aware-review.md`（字数改 source-aware 参考值 + 父 Agent 抽检 rubric）→ `DECISION-20260914`（commit `b28a45c` 修 `persist_summary.py` 透传 `source_chars`）

## 一、用户硬约束（不得违背）

1. **绝不使用绝对值字数区间**。用户实测结论：固定区间导致「为压缩而压缩」——语义破碎、原本的几句话被一句简单概括、丢失原意、笔记读不懂。
2. **内容完整是第一优先级**。压缩原文长度时必须保障内容完整、结构清晰，**不为压缩而压缩**。
3. **字数不足以单独承担质量判定职责**，只能做兜底与失控保护。

> 本约束写入决策文档的目的：防止后续会话再次提出「加字数上限」类方案（已两次被否）。

## 二、为什么必须换掉「字数比例带」（实证，非判断）

### 2.1 这个判据测的不是内容质量

| 批次 | 源（同为 ai-zh 语音识别稿） | 源长中位 | 笔记字数中位 | 比值 | 触发方向 |
|---|---|---|---|---|---|
| 2026-09-14 夏鹏本鹏（长视频） | 零标点 | 5380 | 1051 | **0.20** | 偏短 |
| 2026-09-15 林总linn（短视频） | 零标点 | 1382 | 2673 | **1.93** | 超参考值 |
| 2026-09-15 图灵AI大模型 | 零标点 | ~1800 | 2933 | ~1.6 | 超参考值 |

- 源的口语化程度完全一致，比值却跨 0.20 → 1.93（近 10 倍）→ 判据与「源脏不脏」无稳定因果。
- **同一 structured 模板下**笔记长度：夏鹏批 1051 / 林总linn 批 2673 / 图灵AI 批 2933（差 2.8 倍）
  → 比值主要在测「子 Agent 这次写得长不长」。
- 两端都会误报：源短必报「超参考值」，源长必报「偏短」。

### 2.2 「以前不触发、现在全触发」的真因（时间线）

| 时间 | 事件 | 后果 |
|---|---|---|
| 2026-09-05 | commit `36c085c` 引入机械门禁 | 只有固定字数区间 |
| **2026-09-13** | commit `f95db07` 引入 `review_flags` + 抽检 rubric | 信号诞生（当日仅 3 条） |
| **2026-09-14** | commit `b28a45c` 修 `source_chars` 透传 | 之前 `source_chars` 落 0 → 退化成固定区间，**结构上不可能报「超参考值」** |
| 2026-09-14 晚 | 夏鹏批（同样 ai-zh） | 触发 49 条「偏短」 |
| 2026-09-15 | 本批 212 | 触发 227 行（去重 212 URL）「超参考值」 |

→ 「以前不触发」＝「判据还没跑起来」，**不是稿子干净**。

### 2.3 附带发现：源形态判据（用于后续分流）

- 全库 1228 个 `notes/_raw_*.md`：**897 零标点（语音识别稿） / 331 有标点（公众号长文，密度 0.10~0.13）**，无一带标点的 B站 视频稿。
- B站 字幕优先级（`videos/fetch.py:879`）`[ai-zh, zh, ai-zh, ai-en, ""]` → **ai-zh 第一优先**，人工 CC（`lan=zh-CN`）不在列表内，只能靠 `sub_list[0]` 兜底。
  → **「205 篇是平台字幕」≠「不是机器识别稿」**：205 篇是 B站服务端 ASR，7 篇是本机 Whisper。同属 ASR 产物。
- 因此源形态判据**不能用「是否走 ASR」**，应用：`中文标点密度 ≈ 0` / `行均字数 < 25` / 来源域名。

## 三、新设计

### 3.1 字数（只留两件，均不参与质量判定）

| 用途 | 阈值 | 动作 |
|---|---|---|
| 内容缺失兜底 | `< 300` | 硬拦 |
| 失控保护 | `> max(8000, 源长×3)` | 硬拦（纯防程序跑飞；原长源分支 `源长×0.7` 放宽到 ×3） |
| ~~比例带（超参考值 / 偏短）~~ | — | **整条删除，不再计算** |

> 下限 300 的依据：2~3 分钟、讲得浅、只讲一两个知识点的短视频，本来就写不出多少字（用户决策）。

### 3.2 触发抽检的四类内容判据（替代字数）

1. **硬锚点召回**（治丢点/丢原意）：数字（带单位/大数/年份）· 拉丁术语 · 词典词（`COMPANY_NAMES`/`TOPIC_PATTERNS`/`SOFT_TOPICS`/`TAG_TOOL_SET`）· 6 位股票代码。算召回率，`< 60%` 触发；**源锚点 < 3 时跳过该判据**（分母太小会乱报）。
2. **破碎形态**（治读不懂）：复用 `detect_compression_issues` 的 A 超长句(>140) / B 连环括号(≥2) / C 逗号密度(>0.085)，**从 warning 升级为触发**；新增 D 相邻段落相似度 > 0.85（疑同义反复/注水）。
3. **结构完整性**（治结构不清）：把模板里「必备」模块抽成机器可读清单，缺失即触发。
4. **照搬检测**（治未合成）：笔记 20 字滑窗片段在源（归一化）中的重合比例——**用重合度而非长度**（写长但重组不会命中，逐字搬运才命中）。

### 3.3 抽检的定位：归因飞轮，不是人工兜底

```
机械门禁(形) → 抽检(义) → 归因(root_cause) → 改 prompt/模板 → 抽检退化为哨兵
```

- 内容差的根因在 **prompt / 模板 / 子 Agent 执行**；抽检只是**发现手段**，不是解决办法。
- 抽检记录必须带 `root_cause: prompt | 模板 | 子Agent | 源 | 无`；同一根因累计 ≥3 次 → 触发 prompt/模板修订任务。
- **抽检长期高频命中 = 红灯**（流程有系统缺陷未修），目标状态是每批只随机抽 1~3 篇当哨兵。

## 七、阶段5 语义变更 + 生成侧改造前置（2026-09-15 23:4x，用户决策）

### 7.1 阶段5 从「版本裁决」改为「旧版作废 + 全量重跑」

用户决策（原话要点）：**45 组重名副本都不留**，不做「保留哪一版」的裁决；改为在新版

由此阶段5 拆成两件：

| 项 | 原计划 | 现计划 |
|---|---|---|
| 50 组重名副本 | 逐组裁决留主文件 / 留副本 | **旧版一律作废**（归档到 `_archive/`，不物理删除），登记表改指新版 |
| 重跑 | 不在原计划内 | **新增：队列化全量重跑**，`--force` 覆盖同名（覆盖语义已在阶段3 实现） |

### 7.2 ⚠️ 前置硬约束：**先改「生成」，再重跑**

阶段 0~3 改的是**判定**（门禁判什么 / 抽检怎么触发 / 派单纪律），**未改生成**（prompt、模板、子 Agent 的篇幅与结构策略）。
**沿用现有 prompt 重跑，产出与现库同质，只是重烧一遍 token。**

生成侧三条改造（均由重跑候选清单数据直接推出）：

1. **篇幅由「源的要点数」决定，不由固定区间决定**——源里有 N 个要点就必须有 N 个小节，**禁止合并要点**
   （实测反例：`【人生破局】9大公式` 源 17046 字 → 笔记 988 字，出现 `## 公式三~四` 这类 2~3 要点合并的小节）。
2. **每个要点必须带走源里的硬事实**（数字 / 金额 / 公司名 / 术语 / 年份）——抗压缩最有效手段，且与 `content_signals` 的锚点判据同源。
3. **输出前自检**：要点数是否齐、每要点是否含硬事实、必备模块是否缺——交卷前自查，而不是落盘后被门禁拦。

### 7.3 重跑的两个实测约束

- **源可定位率 77.8%**（`summarized_at >= 2026-09-10`，946 条中 736 条；缺失 210 条集中在【监控】公众号，
  raw 未留存或被同名覆盖）→ **没有源就无法重跑**，只能重抓或放弃。
- **病根 = 笔记长度与源长脱钩**：夏鹏批源中位 5065 → 笔记 938（比值 0.19，150/210 缺必备模块）；
  林总linn 批源 1291 → 笔记 2595（2.02，仅 1 条缺模块）。→ 不是「某个批次坏」，是「长源必被砍」。
- 附带发现：登记表 **183 条指向不存在的文件**（14 条仅路径漂移、169 条彻底找不到，多为早期飞书-only 写入），
  与重跑无关，但反映回链能力有历史欠账。

### 7.4 阶段4 取消

用户决定不改 B站字幕语言优先级（`ai-zh` 维持第一优先），保持现状。
