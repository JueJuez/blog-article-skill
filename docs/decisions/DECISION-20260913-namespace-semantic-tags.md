# 决策：新笔记落盘自动追加命名空间语义标签（方案 A 已落地）

> 状态：**已落地**（2026-09-13 定稿，含下午补丁 + 晚上维度修订）。
> 单一真源：`shared/note_classify.py` · 落盘接线：`articles/main.py:save_summarized_article` · 路由防护：`shared/routing.py:category_from_tags`。
> 关联决策：飞书 frontmatter 于 2026-09-06 刻意停产（YAML 头在飞书同步会被渲染成满屏 `---`）。

---

## 一、目标与根因

- 给**新抓取/总结的笔记**在落盘时自动带上「领域 / 主题实体 / 用途 / 类型」四维度语义标签，
  既能进 `index` 全库快照，也能在 Obsidian 内直接按维度检索（层级 hashtag 原生支持）。
- **存量 1087 篇不回填（决策 C：只管未来笔记）**：旧文靠 `index` 表覆盖检索；新笔记标签与分类器同源。
- 复用现有 `#标签` 行机制（纯 Markdown hashtag，Obsidian 层级 `#投资` 自动命中 `#投资/公司分析`），**不重开 YAML frontmatter**。

### 为什么是这四维（以及什么**不**进标签）

标签的职责是「语义 + 效用」，**不是**「定位」。定位交给文件夹树（区 → 平台 → 来源账号 → 系列），1087 篇已依赖它。

| 维度 | 进标签？ | 理由 |
|---|---|---|
| 层级 / 平台 / 来源 | ❌ 不进 | 文件夹已承担；`path:` 搜索能跨区按作者/来源聚合，标签里再放纯属重复噪声（已实测：`#来源/夏鹏本鹏` 与文件夹 `【我的总结】/作者/夏鹏本鹏` 完全同义） |
| **领域（父/子）** | ✅ 核心 | 语义领域，**独立于来源**——跨账号搜「所有讲投资的」靠它 |
| **主题实体** | ✅ 核心 | 看完最先想到、强相关的实体/主题词（公司/人/工具/概念） |
| **用途** | ✅ | 跨切面「拿来干嘛」（教学可用/素材可用/金句观点/方法论可复用…） |
| **类型** | ✅ | 体裁（读书笔记/观点随笔/案例拆解…） |
| 状态/价值（精华） | ❌ 不做 | 自动判断不可靠、易成脏数据；若想要星标体系做成**手动** `#精华` |

---

## 二、决策：采用方案 A（命名空间嵌套 hashtag，4 维）

不引入结构化 frontmatter，只在 `tags` 列表里追加带命名空间的标签，由 `format_note_with_prompt` 统一加 `#` 输出。
语义标签**自动生成**：领域/用途/类型由代码分类器推导（与 `index` 同源）；**主题实体维度唯一破例交由总结 LLM 在生成时顺手输出**（见第三节），其余保持纯自动、与 index 同源。

### 落地后一篇新笔记的标签行（终态示例）

```
#投资/公司分析 #topic/伊利股份 #topic/护城河 #topic/价值投资 #用途/教学可用 #类型/结构化复盘 #更早
```

> 注：分类器返回**不带 `#` 前缀**的命名空间串（如 `投资/公司分析`），由 formatter 统一加 `#`，避免双井号（`##`）。

### 四维度命名约定

| 维度 | 命名空间 | 示例 | 检索写法 |
|---|---|---|---|
| 父领域 / 子领域 | `#父/子` | `#投资/公司分析`、`#投资/宏观`、`#商业/虚拟产品`、`#AI科技/AI编程`、`#个人成长/读书方法`、`#综合/未分类`（锚点） | `tag:#投资/公司分析`（命中子领域）/ `tag:#投资`（命中全部投资子领域） |
| 主题实体 | `#topic/…` | `#topic/伊利股份`、`#topic/小红书`、`#topic/Claude Code`、`#topic/护城河` | `tag:#topic/伊利股份` |
| 用途 | `#用途/…` | `#用途/教学可用`、`#用途/素材可用`、`#用途/金句观点`、`#用途/选题方向`、`#用途/方法论可复用` | `tag:#用途/教学可用` |
| 笔记类型 | `#类型/…` | `#类型/结构化复盘`、`#类型/案例拆解` | `tag:#类型/案例拆解` |

### 组合检索示例（Obsidian 搜索 / Dataview）

- "投资·公司分析 里能当教学案例的、讲伊利的"：
  `tag:#投资/公司分析 AND tag:#用途/教学可用 AND tag:#topic/伊利股份`
- "所有金句类口播素材（跨领域）"：
  `tag:#用途/金句观点`

## 三、实现要点（代码侧）

- **`shared/note_classify.py`**（正式模块）：
  对外 `infer_semantic_tags(content, folder, author, note_type, url, source_account, topics=None)`。
  - **主题实体维度（唯一 LLM 维度）**：`topics` 非空时直接用 LLM 产出（截断到 5、去空去重、`/`→`·`）；`topics` 为空/None 时退化为代码关键词正则抽取 `extract_topics`（无 LLM 主题词时的兜底，如批量迁移路径）。
  - **LLM 主题词区块**：总结时 LLM 在笔记末尾独占一行输出 `【核心主题词】复利 | 护城河 | 价值投资`，落盘前由 `extract_and_strip_topics` 提取并**从正文移除**（转为 `#topic/` 标签，不留在笔记里）。指令写在 `prompts/templates.py` 的 `UNIVERSAL_RULES`（轻模板共享）**与** `CONTENT_SUMMARY_PROMPT`（structured 自含，未拼 UNIVERSAL_RULES，须单独内联）两处，确保**所有 note_type 都拿到**。
    - 数量硬约束：**推荐 3–5；可少于 3（甚至 1–2），但不可多于 5**；标准＝「看完这篇你最先想到、且删掉它这篇文章就不完整」的强相关词；宁缺毋滥，禁止凑数。
  - **领域标签**只输出含 `/` 的子领域（如 `投资/公司分析`），绝不输出裸父级抢「分类」。
  - **`综合/未分类` 锚点**：没命中任何领域（parent 为 None/综合）时落到 `#综合/未分类`，保证**每篇都有领域维度**（不再静默丢弃导致语义维度塌掉）。
  - 主题实体名里的 `/` 替换成 `·`（如 `Agent/智能体` → `topic/Agent·智能体`），避免三级层级。
- **`articles/main.py`**：
  - `summarize_content`：拿到 LLM 总结后调用 `extract_and_strip_topics` 剥离主题词块，并在返回 dict 中带 `topics`；
  - `summarize_and_save` / `save_summary_only`：把 `topics`（或正文块提取结果）透传给 `save_summarized_article`；
  - `save_summarized_article`：落盘前再剥离一次区块（幂等），计算 `effective_topics`（显式 topics 优先，否则正文块），传入 `infer_semantic_tags`；注入后移除裸作者标签（作者已在文件夹路径，`path:` 可聚合，裸标签纯噪声）。
- **`shared/routing.py:category_from_tags`**：跳过含 `/` 标签（命名空间标签绝不抢「分类」）。

## 五、范围与遗留

- **存量 1087 篇不回填（决策 C：只管未来笔记）**：旧文靠 `index` 表覆盖检索；新笔记标签与分类器同源。用户已确认不花 LLM/改文件成本回填。
- **标签生成模式（2026-09-13 晚上定稿）**：领域/用途/类型保持**纯自动**（与 `index` 同源、信号稳定）；**仅主题实体维度破例交 LLM 生成**——理由：该维度要的「看完最先想到、强相关」靠代码正则抽不全（旧 `extract_topics` 在读书/职场类内容全库 0 命中），且只破例一个维度、其余仍与 index 同源，不会造成两套标签源分叉。

## 六、补丁记录（2026-09-13）

### 下午：标签去重 + 分类器纠错 + 去掉无信息量标签
上线后消费两篇夏鹏（读书/职场 UP）笔记，发现标签行存在**重复**与**不适配**两类问题，已修复并定稿：
- **重复**：入队预填的裸作者标签（如 `夏鹏本鹏`）与命名空间标签同义双写。修复：注入语义标签后移除被命名空间覆盖的裸标签；作者本身已在文件夹路径，裸作者标签一并移除。
- **不适配（错归投资）**：`note_classify.py` 曾把 `【我的总结】/作者/<账号>` 一律无脑兜底 `投资`，且 lede 二次校验刻意排除 `parts[1]=="作者"`。修复：①作者归档笔记 `parent=None` 交导语粗判；②开放 lede 二次校验；③父领域推断**完全内容驱动**——`parent_from_lede` 是平级 `(域名, 正则)` 通用分支（投资/商业/AI科技/内容创作/个人成长…），**不在路由映射里按作者硬编码**。**扩展点**：新增父领域只需在 `parent_from_lede` + `subdomain_from_lede` 追加分支，路由无需改动。
- **去掉无信息量标签**：`#文章总结` / `#转载` 对落地使用无实质帮助，不再生成。
- **验证**：`tests/test_note_classify.py` 13 项全过；两篇夏鹏笔记已用最终逻辑重落真实库。
