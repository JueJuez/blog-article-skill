# DECISION-20261019-b-group-closeout
## 背景
用户带来下游 `D:\Code\project\article\writing-studio` agent 对知识层 B 组（下游受益）六项的
优先级排行（B1>B3>B2>B6>B4>B5），逐条复核后讨论是否实施。复核对象是本仓库
`PLAN-20261018-knowledge-layer.md` §6 的 B 组（该计划为 2026-10-18 快照，此时 B 组尚未开工）。

复核发现计划原论据中三条已被现实推翻：
- **B1**（【监控】判「对标」→ 降权 0.7 + 限篇数）：下游已于 2026-10-18 移除类型加权与「对标」
  限数（`knowledge.ts:11`/`:461`），排序改为纯检索相关度；`classifySource` 仍返回「对标」但
  仅作展示标签、不参与排序。→ 原「62% 库存被降级」论据失效。
- **B3**（published_at 契约）：原文断言「我们 frontmatter 里已有」是采样偏差——全库仅
  **107/2333＝4.6%** 有该字段（集中在 2026-06~08 少数重做过的账号）。但**文件名 `YYYYMMDD_`
  前缀覆盖全库 90%**，而下游 `draftPrompt.ts:137` 已把 `s.path`（含文件名日期）注入 prompt；
  下游对 `publishedAt` 的实质消费仅此一处注入（`kbSync.ts:120` 只排 RSS 快照、与本地库无关；
  `writingBrief`/`qualityState`/`quality` 仅记录/签名），**无任何按日期排序或过滤本地稿的逻辑**。
- **B6 前提**（「867 篇【我的总结】是 L2 雏形」）：实测 867 篇中 **830 篇带唯一 BV 号 + 来源链接**
  （与【监控】同一套模板），**多源/跨源篇数＝0** → 它们是**单源笔记**，不是整合产物。
  **库内不存在跨源整合层（L2）**（全库 2333 篇全部为 L1）。
- **B2 附加值**：L1 稿自带宽的速览块（实测头部含「30秒速览/TL;DR/一句话核心」者：【监控】87%、
  【我的总结】89%），索引行能提供的"一句话摘要"L1 已有；且下游为检索型消费者
  （`KB_TOP_K=4` + `boost:{title:3}`），索引页作为 md 进池会抢素材坑，隔离需改下游。

## 决策
- **B 组全部结项，无一保留**（B1 已由下游解决；B2/B3/B4/B5/B6 均不做）。三条通用理由：
  ① B 组功能**我们自身也用不上**（我们不读自己的库）；② 下游需求**已自行解决或本就不需要**；
  ③ 剩余项**收益过低或前提不成立**。
- 逐条证据与作废/更正痕迹写入 `PLAN-20261018-knowledge-layer.md` §6「B 组结项说明」
  （原论据加删除线保留，不删原文），并同步 §3.1/§3.5/§9/§11.4/§12.3 与 `docs/README`。
- **published_at 可在新稿顺手写入**（零成本、字段自然补齐），但**不做全库回填、不推下游改解析**。
- 知识层计划自此仅余 A 组（自身受益）为有效产出；A 组已于 2026-10-18 全部验收。
- 遗留观察项（**笔记变长 +173% 未被 prompt 修订压下、超长句 50% 高于基线 33%**）仍属有效待办，
  不随 B 组结项一并关闭。

## 不做什么
- 不建 L2（跨源整合层）：成本高（须从 2333 篇 L1 从零合成）、下游 agent 认为不可靠，且下游
  自身的生成稿动作就是一次跨素材聚合，静态 L2 层与之重复。
- 不建索引页（B2）、不做源快照库挂第二 source（B4）、不做引用指针持久化（B5）。
- 不推动下游修改 `sourceType` 语义判定（B1 已无需改；`classifySource` 的「对标」标签保留现状）。
- 不为 B 组单开评估轮次或探针（原「B2 同时是 B6 探针」一并取消）。
