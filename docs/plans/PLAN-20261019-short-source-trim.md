## 1. 问题（A4 正式轮 30 篇实测，非推断）

A4 落地后笔记变长 **+173%**（旧稿总 123,471 字 → 新稿 295,518 字）。同一轮判分保留率 84.2% → 99.4%。拆开看，「变长」**不是**注水（无编造、无重复），而是**分类别、按源长严重不均**：

| 源长桶 | 旧稿/源长 | **新稿/源长** | 旧事实密度 | 新事实密度 |
|---|---|---|---|---|
| 0–2k | 0.99 | **2.95** | 3.3 | **2.0**（−37%） |
| 2–5k | 0.68 | **1.83** | 9.5 | **7.9**（−17%） |
| 5–10k | 0.48 | 1.15 | 12.6 | 9.3（−26%） |
| 10–20k | 0.40 | 0.81 | 18.4 | 16.3（−11%） |
| >20k | 0.30 | 0.81 | 27.5 | 21.0（−24%） |

口径：事实密度＝笔记中**能在源里找到的数值**/千字（按数值比对，忽略 `%` 与单位差异；**不含**标题行，否则 `### 10.1` 这类小节编号会被算成数据）。

**两条关键事实**：

1. **新增内容按方式拆**（全轮新增 5,426 字/篇）：**源内容展开 76%**、分析/推断 11%、元层复述 5%、应用/行动 4%、反例/踩坑 3%、引流 1%。→ 现状是「把源一个点拆成 背景/因果/证据/结论 四块写满」（A15 由 16 节 → **71 节**），不是加新维度。
2. **两种源本质不同**（每篇新增，字）：

   | 桶 | 源内容展开 | 分析/推断 | 元层复述 | 应用/行动 | 反例/踩坑 | 合计 |
   |---|---|---|---|---|---|---|
   | 0–2k | 821（**37%**） | 487（22%） | 302（14%） | 293（13%） | 290（13%） | 2,212 |
   | >20k | **10,412（90%）** | 753（7%） | 291 | 1 | 130 | 11,587 |

   **长源新增 90% 是真的源内容展开（正当，不动）；短源只有 37% 是源内容展开，其余 63% 是模板加成**。而短源基线保留率本已 ~100%（A02/A05 就是 100%）→ **短源没有「信息」可扩展，多出来的都是「层」**。

**质量三维结论**（供对照验收）：忠实性**好**（新增数值 93% = 179/193 源内可查；失真观察 0/30；A25 的对比表是源数据重组，表内专名源里全在）；重复度**无**（节间 8-gram 近重复 0%）；信息密度**降 21%**。

**对下游的真实代价**：下游 `knowledgePassages.ts:selectEvidencePassages` **每篇素材最多取 2 段**（≈≤3.2k 字），故变长**不**抬高每篇素材的 prompt 成本；代价是**命中的 2 段里有效锚点少了约 1/5**。`PLAN-20261018` §8 原文「笔记 2.7 倍长对下游是真实成本（检索上下文变贵）」**不准确，本文档为准**。

## 2. 目标 / 非目标

**目标**：短源（≤5,000 字）新稿的 **稿长/源长回到 ≤1.5**、**事实密度回升到 ≥ 旧稿水平**，同时**保留率不降**（≥ 现状 99.4% 的量级，允许 ±方差）。

**非目标**：
- 不动长源（>5,000 字）——其扩展 90% 是正当的源内容展开。
- 不重做存量（全库 2,333 篇不动）；本改动只影响**此后新生成**的短源笔记。
- 不做「合并视角」式的库存改写（那是记忆 `project-meta-layer-redundancy` 的独立议题，用户未裁决，勿混）。

## 3. 改法

### 3.1 常量与阈值（单一阈值 + 按小节性质定去留）

| 常量 | 值 | 真源 |
|---|---|---|
| **短源模式开关**（本改动） | `SHORT_SOURCE_MAX_CHARS = 5000` | **新增**，放 `prompts/section_budget.py` |
| 既有「源撑不起」阈值 | `THIN_MAX_CHARS = 2000` | 已存在，`prompts/extract_checklist.py:35`；**用途不同（A4 的 T0 自报），勿混** |
| 阈值口径 | 源文本去空白字数 | `prompts/templates.py:source_chars_of()`（既有统一出口） |

**为什么只有一个阈值、不分档（2026-10-19 定）**：源长只决定「是否进入短源模式」（开/关一个开关），**具体关停哪些小节由小节自身性质与条件决定**（§3.3），不由长度再分档：

- 数据上 5,000 是自然分界——`≥5k` 的稿长/源长已 ≤1.15（接近正常），`≤5k` 的 0-2k 为 2.95、2-5k 为 1.83，**两档都超标，同一套规则都能治**。
- 分长度档会让规则文本与验证面翻倍，而 2-5k 是否「被治过头」应**由 A/B 数据回答**，不预先假设；若本轮显示 2-5k 掉了必要内容，再拆档（数据驱动）。
- 因此：`source_chars > 5000` → 返回空串（长源一行不动）；`≤ 5000` → 进入短源模式，按 §3.3 清单执行。
- 与既有 `THIN_MAX_CHARS=2000` 是**嵌套关系**（`<2000` 时 A4 的「源撑不起」自报会同时生效），互不冲突。

要求：档位判定必须能被 `--check` 自报（打印「本篇源长 X → 短源模式=是/否 → 关停小节清单」），不留隐式分支。

### 3.2 代码落点（三处，均为线性主干）

1. **新增渲染器** `prompts/section_budget.py::render_section_budget(source_chars, note_type) -> str`
   - 返回空串（`source_chars > MID_MAX_CHARS`）或「短源/中源模式」指令块；
   - 内容＝**本文档 §3.3 的白名单/黑名单**的显式文本（要求模型「本篇不得写下列小节」+「只做下列扩展」）。
   - 参照既有范式 `prompts/extract_checklist.py:122 render_extraction_rules(source_chars)`（按源长 switch、纯函数、无副作用）。
2. **注入点** `prompts/templates.py:969 get_note_prompt(note_type, source_chars)`
   - 在现有 `+ render_coverage_guide(...) + render_extraction_rules(...)` 之后追加 `+ render_section_budget(...)`。
   - 该函数已是全链路唯一 prompt 出口（`articles/main.py`、`videos/main.py:_finalize_single` → `provenance.dispatch_fields` 都经它），**无需改调用方**；`source_chars` 已在传（A4 用同一参数），无需新增管道。
3. **门禁同步（见 §3.4）**——`prompts/content_signals.py` 的 `structure_missing` 目前**不吃源长**，短源关停小节会与 `required` 冲突。

### 3.3 扩展类型白名单 / 黑名单（本改动的语义核心）

**黑名单——短源一律不写**（这些是「给人复习」的层，对下游写作零价值，且是膨胀主体）。
下表**前 5 行即代码黑名单**（`prompts/section_budget.py::_BLACKLIST`，逐节对应一个模板关键词，
只对「该类型模板里确实存在」的小节生效）；末两行**不收进代码黑名单**，按白名单/既有口径处理：

| 小节 | 模板位置 | 备注 |
|---|---|---|
| 延伸思考 + 我的想法 | `templates.py:163` | 模板原标「按需」，但无机械判据 → 短源照样出 |
| 自测三问（检索练习） | `templates.py:357` | 同上 |
| 讲出来（费曼技巧） | `templates.py:358` | 同上 |
| 笔记者分析（思维模型透镜） | `templates.py:44`、`:641` | 泛化推断，**方向性错误机械测不出** |
| 小结闭环 | `templates.py:130` | 基本纯复述 |
| 关键术语卡（**不入代码黑名单**） | `templates.py:143` | 该节**条件化保留**：仅当源里有作者私房术语，且只写「与常识用法的差异」一行（见白名单 4）——整节禁掉会丢掉术语卡里唯一有增量的列 |
| 文末引流（**不入代码黑名单**） | §12.2-3 既有口径 | 按 `DECISION-20261018-info-coverage-scope` 处理（孤立纯推广删、流程内推广保留标【推广】）；不是「小节禁写」问题，块里只提一句不单设小节 |

**白名单——短源该做的扩展**（按价值排序；前三条为已确认，后两条为收窄后的窄口）：

1. **重组**（源数据重排为表/矩阵/时间线）。唯一「字数变多但密度不降」的形态；A25 的对比表即此。
2. **条件 / 前提 / 适用边界**——源给了做法但未说「仅当 X」。**必须标注来源或「（笔记者推断）」**；这正是下游要的「限定」。
3. **有信号的反例 / 失效场景**——**仅当源侧机械信号触发**才立节（复用既有 `SECTION_CONTRACTS[*].conditional` 的 `counterexample` 信号，`content_signals.py:334`，判据＝「反例」≥1 处或「例外/恰恰相反/误以为」类 ≥2 处）。**禁止为填节编反例。**
4. **作者私房术语与常识用法的差异**（新增类型的窄口）：**仅当**源里作者自定义了某词才写，且只写「与他义/常识用法的差异」一行（模板 `templates.py:143` 已有此列）——这是术语卡里唯一有增量的部分。
5. **被反驳 / 对立观点**：**仅当**源里作者明确反驳了某说法才记（不代作者设想反对意见）。opinion 类已有「正反双方」（`SECTION_CONTRACTS` opinion.source_dependent）。

**不做（易被误当「扩展」）**：

- **证据性质标注**（原拟做，2026-10-19 用户否决）：拟把「非事实类」主张标成「作者转述/判断/假设」。否决理由——**这类句子前面本就带「据说/假设/可能」等词**，语义已自明，再加固定标记属重复、且会稀释信号。模板 §八（`templates.py:197`）「保留不确定性、可标『作者认为…』」与 A4 清单的 `亲历/判断/假设/引述` 分类**维持现状**，不再收口。
- 源外背景补充（除非已核实并标注；模板 `templates.py:44` 已定此红线）、泛化推断与读后感、凑数反例、数字的单位/口径「换算」（若做须同时保留源原话，低优先，不纳入）。

### 3.4 契约冲突与处置（**已决 2026-10-19：保留速览**）

`SECTION_CONTRACTS`（`templates.py:919`）里 **`分层速览` 是 `structured`/`general`/`reading` 的 `required`**，而 `structure_missing(note, note_type)`（`content_signals.py:284`）**不吃源长** → 短源若不出速览，机械门禁会报 `missing`。

**裁决（用户 2026-10-19）：短源保留「分层速览」**，只关 §3.3 黑名单里其余各项。理由：速览是**压缩 gist**（约 100–200 字，「30秒速览 + 核心公式」），是「再走一遍」各层里**成本最低、下游与索引层最需要**的一层（B2 索引行想要的一句摘要就是它）；关它省不了多少字，却要动 `required` 契约与门禁签名。

→ **本改动不改 `SECTION_CONTRACTS`、不改任何门禁签名**，只做生成端的 prompt 级小节约束（§3.2 第 2 项）。

| 1 | 保留率 | 0-2k 100% / 2-5k 100% | **不降**（≥ 现状，允许 ±方差） |

## 5. 边界与风险

- **接线覆盖（2026-10-19 实测调用点，非文档推断）**：`articles/main.py:568`、`prompts/provenance.py:40`（条目 prompt 出口，单篇视频 / 系列课单集 / 监控 ASR 批量都汇于此）、`scripts/backfill_series.py:175`、`scripts/build_refetch_resum_batches.py`、`scripts/consume_migrate_queue.py:185` **均传源长 → 短源块均生效**。例外两处与 A4 **完全相同**：① `videos/main.py:83` 的外部 provider 直调分支（`FORCE_AGENT_MODE=0`，默认关）；② `videos/main.py:606 _build_subagent_prompt`（**死代码**，自 2026-07-21 起零调用点）。两处都不传源长，故不带本块。
- **短源≠低价值**：一份 1,500 字的观点文，其「观点 + 限定条件」本身就是全部价值，不该被展开稀释。本改动不减少这类内容的保留。
- **逆例风险**：短源里确有值得深挖的（如含公式/反例/术语），此时**靠 §3.3 白名单的 2/3/5/6 条件触发**保住，不是一刀切删。
- **下游未验证**：密度回升对下游写作质量的**实际增益未测**（下游侧才能测）。本改动只保证「不损坏 + 密度回升」，不宣称提升下游产出。
- **A6 交互**：A6 的 `conditional` 五信号（反例/公式/章节/对比/数值密集）在本改动里**继续生效**（黑名单不含这些信号触发的**内容**小节，如「核心公式」「对比矩阵」），只关「分析/元层」。两改动的隔离用 `--prompt-profile` 分开跑。
