### 3.2 统计最小口径

| 统计项 | 口径与限制 |
|---|---|
| 批次及版本 | 关联 batch、queue id、实际源/稿版本、可获得的生成 prompt 及审核 prompt hash；历史未知项保留 unknown |
| 处理量 | 本批选中、发包、有效回收、未回收、error/stale/skipped、剩余 pending；本批增量和历史累计分开 |
| 问题 | 机械疑点数、经回源确认的真错/误报/未确认数，以及独立审核额外发现的问题；同一疑点按定位去重 |
| 修订 | 修订次数、回审结果、修订前后稿 hash、是否正式保存、仍待处理的问题；修订前的原始结果保留 |
| 消耗 | 可获得的 token/usage、模型调用记录、审核耗时、人工分钟；未知写 not_exposed/unknown，不写 0；模型耗时不得冒充人工时间 |

误报率仅以“已裁定机械疑点”为分母；未确认项不算误报，也不算真错。样本只代表被选批次；风险优先样本不能估算全库错误率。队列为空、命中为零、报告生成成功均不能单独称为质量通过。

语义保留率只在后续固定必留清单的配对样本内计算；不得将关键词命中率、字数比例或机械 A5 结果包装为逐篇语义分数。

### 3.3 首轮消耗边界与验收

首轮默认最多 **5 次独立审稿轮次，包含修订后重审**，选单时为可能的重审预留名额；至少保留一个普通随机样本名额，样本不足如实记缺额。全文分块会增加实际调用数，必须计入消耗，不能把“五轮”说成“五次计费调用”。派单前核对源/稿长度与本次可用额度，预算不足缩小批次，不截源冒充全文审核。具体货币预算暂未设定，不能承诺节省金额。

确认问题后每稿最多修订两次，重审一并受本批额度约束；本批用尽就记录待处理并停止，下一批继续，不自动扩大批次。不默认清空现有 pending，也不全局开启保存前 `NOTE_QUALITY_GATE`。

### 5.2 已确认的源图处理原则（2026-10-27，待实施）

源文可能用文字和图片共同承载知识；只抽文字造成的信息丢失，不能归咎为原作者“写得不清楚”。也不能因为页面有图就推定正文缺信息。

| 图与正文的关系 | 处理目标 |
|---|---|
| 装饰图或完整重复正文 | 通常跳过识图与原图保存；保留现有台账即可 |
| 含正文未写出的数字、步骤、条件、层级或关系 | 按需读取，将重要信息写成可检索的文字/表格，并保留原图定位 |
| 界面操作、复杂布局、数据截图等需回看核对 | 提取重要内容，同时按需保存原图及来源；资产位置沿用本地库现有约定 |
| 图不可达、模糊或无法确认是否含独有信息 | 明确未读/部分读取与缺口，不凭 alt、标题补造图内内容 |

2026-10-27 已核对下游 `D:\Code\project\article\writing-studio` 的 `src/lib/knowledge.ts:walkMd/readLocalDoc` 与 `src/lib/draftPrompt.ts`：当前本地取材扫描 `.md`，将文本摘录送入写作 prompt。**单独保存图片不等于图内内容可检索或已送入模型**。原图作为回看证据，文字化内容作为当前检索链路可用素材；本轮不改下游为多模态检索。函数名接手时须现场复查。

### 6.4 已确认的表达原则与生成时机

| 读者需要完成的事 | 优先候选形式 | 不适用时 |
|---|---|---|
| 在相同维度上比较对象、参数、成本、适用条件 | Markdown 表格；只有源有的信息才列，条件不同须说明不可比 | 不凑列、不猜缺失单元格，短内容可用文字 |
| 理解分支、并行、汇合、循环、交互或空间层级 | Mermaid 结构图/流程图；保留条件与方向，节点用简短表述 | 简单步骤或短清单用文字/列表，不逐段照搬进方框 |
| 看同口径数据的趋势、差距或构成 | 现有 chart 数据块；主体/单位/时点一致，精确数值仍可回查 | 数字组数够也不强制画；不可比或信息不足时不画 |
| 理解单一观点或简短操作 | 自然段或列表 | 零图、零表可以合格 |

- **每篇判断，不设每篇必须生成的配额**；箭头数、链长、数字组数只用于发现候选，不能单独触发强制生成、重做或质量扣分。
- 先读懂源并确定内容组织，再随成稿生成适合的表格/代码图；不默认加独立绘图模型调用。Markdown/Mermaid/chart 会增加输出与核对成本，不称零成本。
- 图表承担比较、关系或趋势，正文保留解释、证据及重要限定；图表与正文的互补不等于把知识只留在图片里。已有精确数据表不因加图而丢弃。
- 保存前核对数字归属、单位/范围、连线方向、条件与因果属性，检查目标端实际渲染。**可渲染不等于语义正确**；源不支持的因果边或数据不能为了画图补齐。

## 9. 输入端优化与输出目的（2026-10-27 讨论结果及后续计划）

### 9.1 已确认的定位与输出目的

确认来源为本次用户讨论：项目主打自动监控抓取并总结，围绕内容总结、知识笔记两种产物重心；下游 Agent 是输出路径，首要目标是提供完整、可追溯的素材。用户要求先记录结果并给开发计划，再讨论输出模板及内容质量；延伸部分当前不做，后续可另行优化。

- **内容总结**帮助理解作者讲了什么、主线怎样推进、为什么得出结论；**知识笔记**保留可理解、检索和取材的观点、机制、案例、步骤、数据、资源及边界。两者可共用材料底座；本次不据此新增两个 `note_type`，也未确定必须分两份文件或固定两层版式。
- 在已获取、实际读取的源范围内保住有效信息与关系，并能准确回源；笔记保有理解必要的上下文，不要求下游重新打开每篇源才能读懂。未读附件、图片、视频画面或全书不能声称已覆盖。
- 完整性按独立有效信息及其关系判断：主线、独立观点、论证/因果过程、案例、步骤、数字口径、资源、条件、例外与不确定性均有落点；主线外有独立取材价值的信息也保留。重复表达可合并，寒暄和纯过渡可去掉，独有信息不随合并消失。
- 忠实保留主体/说话者、时间、数据归属、亲历/转述/观点/预测/假设属性及结论强度；记录作者说法不等于已外部核实，不把单案例经验升格为普适规律。
- 面向片段取材，条件就近绑定结论，单独取段仍知道对象、必要背景和限制；重要信息有可用的来源定位，整篇 URL 只是基础。
- Agent 数量、字数、小节数、有无图表、材料格式或机械 token 命中率均不能单独证明输出质量；评价细则在 S5 讨论。

### 9.3 输入端方向与候选分工

候选流程：**现役抓取工具 → 保真原始材料及定位 → 独立提炼 Agent → 按模板生成 Agent → 按风险对照原文复核**。方向已确认，净收益及全量适用性尚未验证。

1. 素材层以确定性工具为主，复用文章、字幕/ASR、CDP 与图片台账入口，保留可获取的标题层级、段落、表格行列、图片/图注和字幕时间位置，标明读取范围与缺口。识图等语义任务按需交给模型，不默认增加抓取 Agent。
2. 提炼层交付**主线地图**（问题、推进过程、判断与结论）、**信息条目**（观点/案例/步骤/数字/资源/条件/反例及来源位置）、**关系说明**（证据支持哪个观点、步骤依赖什么、例外限制什么）。原话、摘意与关系归纳区分；以单源信息组织为范围。
3. **先按原文提炼，再按输出模板组织**，不能因为模板没有栏目就丢掉信息。清单帮助对账，不充当必须逐项扩写的大纲。
4. 原始材料保留且可回查；条目关联同版源位置，写作与审核均能读原文。复核包含原文→提炼/成稿的遗漏检查，以及成稿→原文的支持检查，防止上游漏项被下游继承。
5. 独立步骤使用自包含任务和必要材料，隔离无关会话与旧稿修改史，同时保留全文主线及必要邻文；不因分段切断指代、条件和跨段关系。不同模型不作为必需条件。
6. 优先在长源、复杂论证和图文混合材料试验，保留简单短源对照；根据具体缺口选择分段提炼、识图或独立复核，不预设每篇增加同样数量的 Agent。

- 继续条件建议沿用本计划的小样本决策尺度：至少两个不同源出现可定位改善、无新增严重失真、短源不因强制多步骤明显退步、消耗可接受。该尺度不证明统计显著或全库通过；严重度、成本限额和改善判据在 S5 确定，派发前按额度缩批，不无限调参。

### 9.6 实施时要验证的边界

本次只列场景，不创建占位测试或启动开发；实际实施时按已定契约补 pytest RED 用例。

- 条目的源位置、原句、源 hash 或材料版本失配时不能当有效交接；换源/改稿使旧提炼或旧审核失效，缺证据不伪造追溯链。
- 表格数字不串行串列；主体、单位、期间、分母及假设属性随条目保留。结构字段可机械检查，归属和论证关系另做语义核对。
- 图片未读、附件不可达、只有文本/字幕等保留真实访问范围；读图文字化不冒充完整结构理解，ASR 疑数不补精度。
- 分段保留主线和必要邻文，检查跨段指代、条件与因果；字符范围完整不等于理解正确。
- 提炼超时、无效返回、材料包不完整或生成中断时保留源及已完成产物并支持幂等续跑；重试/回退细则在 S5/S7 确定，失败不得登记成功、丢失队列或覆盖旧好稿。
- 按改动复用 `tests/test_extract_checklist.py`、`tests/test_type_provenance.py`、`tests/test_image_inventory.py`、`tests/test_build_round_profile.py`、`tests/test_async_review_batch.py`、`tests/test_fulltext_semantic_review.py`；不为文档写实现镜像测试。实现、离线验证、真实执行、语义结果、消耗和发布分别记。

### 9.7 九类模板微调（讨论方案，待实现）

用户本轮要求把上一轮模板与内容质量讨论写入开发文档。下列为据当前代码提出的调整方案，尚未改生产或完成效果验证；质检的新建议另见 §9.9，不把联网调研直接当作实施验收。

总体保留九类入口和已有来源忠实/覆盖优先机制，先统一公共规则，再调整各类栏目。当前 `general` 与 `structured` 共用基础 prompt；不为“内容总结/知识笔记”新增平行分类体系。

| 类型 | 保留的组织重心 | 微调方向 |
|---|---|---|
| structured | 概念、机制、步骤与条件 | 背景、痛点、价值、公式等按源准入，不要求每篇填满所有栏目 |
| key_points | 独立观点及其论据 | 保留完整论证，取消无源行动项、推导另一面反例和延伸；源内明确行动建议保留 |
| case | 背景、约束、决策、动作与结果 | 经验有源依据，不自行补成败原因、通用规律或迁移建议 |
| opinion | 立场、论据、限定与源内争议 | 不另造反方、认知误区或个人立场，保留作者已有反驳 |
| interview | 话题、问答、人物立场与交锋 | 允许按话题归组，保住问答对应、必要推进顺序及后续纠正/让步 |
| roundup | 对象、可比维度、差异与条件 | 推荐服从源内证据，缺失维度不补，不按模型常识强排名 |
| reading | 所读范围、主张、论据与边界 | 不从单集推全书，关闭额外书评、外部争议和迁移练习；源作者自己的分析照常保留 |
| dissection | 已有打法、创作结构、数据与案例 | 收紧无源机制解释、跨案例拼接规律及套用建议，不把预置平台经验写成源内事实 |
| general | 无明确特化形态时的兜底组织 | 跟随实际主线，不默认将所有材料套成教程 |

- 公共条款统一关闭 Agent 额外生成的思维模型分析、反驳、类比、迁移和个人留白等；自测/费曼等附加学习栏目本轮不默认生成。**原作者已有的分析、反驳、类比、方法、练习和迁移内容属于源内信息，仍需保留**，不能按栏目关键词整段删除。
- 正文中的“固定结构/顺序不可颠倒”改为模块准入与组织原则；署名、标签、来源和最终格式化等系统契约继续由现有管线管理。小节数量和模块存在本身不算完整证明。
- ASR 清洗只修能由上下文确证的转录问题，术语、人名、疑数保留不确定性；不把“必须主动修正”解释为可凭常识补精度。
- 同步具体模板、公共规则、描述、自检、`SECTION_CONTRACTS` 和审核口径，防止正文允许省略而门禁仍要求旧栏目，或关闭延伸后审稿仍因缺洞察扣分。S4 隔离试验未见收益的图表条款不直接推广。

### 9.8 内容编排与质量边界（讨论记录）

核心原则：**忠于原文的含义与论证关系，正文表达顺序可受约束地重组**。观点忠实、信息完整和组织清晰同时成立；无需照抄原章节顺序，也不能以重组为由减少独有信息。

| 可调整的表达 | 必须保护的关系 |
|---|---|
| 核心结论提前 | 条件、例外、不确定性与结论强度一起保留，首屏不升格 |
| 分散内容按主题归组 | 各自立场和适用范围可区分，不把不同观点并成统一结论 |
| 合并重复说法 | 每处独有事实、机制、案例、条件与资源仍有落点 |
| 结果前置、再回顾过程 | 标清事件真实时序、决策转折、操作依赖和因果，不写反先后 |
| 按话题整理访谈 | 保留问答对应、说话者及后续更正、让步和分歧 |
| 文字转表格/列表/结构图 | 对象、单位、期间、条件及关系不变，不拼口径或加因果边 |
| 改写为清楚的书面语 | 原意、归属和不确定性不变；标作原话的片段保持准确 |

补充要求：源内已有证据跟随它支持的观点；非主线但有独立取材价值的信息可以另行归组；片段保有必要背景及就近限定。源没有解释的术语/原因不能凭常识补成作者原意。正文可用与追溯粒度的具体呈现仍需实现时确定。

### 9.9 质检最小方案（本轮建议，尚未实施）

“在原文找到”是追溯基础。应核对**同一版源是否支持整条陈述，以及重要源信息有没有漏掉**：数字出现过但挂错主体、营收改利润、可能改必然、条件被删或把相关写成因果，都可能通过简单命中检查；输出的每句话都正确也仍可能漏掉整段关键论证。

| 检查 | 核对内容 | 典型失败 |
|---|---|---|
| 有据：稿→源 | 重要陈述能定位到完整支持它的源片段；可跨多个片段，但各自位置明确 | 引用相关却不能支持该结论，或只支持复合句中的一部分 |
| 保真：含义与关系 | 主体/说话者、时间、单位/分母/口径、假设、条件、否定、因果、顺序和强度一致 | 数字没变但归属/指标变了，可能性被写成确定结果 |
| 完整：源→稿 | 源内有效观点、论证/机制、案例、步骤、条件、反例及独立补充信息有落点 | 句句有据却漏掉失败条件、论证链或关键案例 |
| 可取材：片段使用 | 只看所取段落，能理解对象、必要背景、依据与限制，关键内容可回源 | 指代悬空、限定远离结论、图中信息没有可用文字 |

**执行建议**：复用当前机械门禁、自检、接地审计、异步复核队列和有界批次；机械缺陷由工具检查，作者自检覆盖上述要求，独立语义复核对高风险条目和随机样本执行。保留随机样本以观察无机械信号的漏项，不把“未触发风险”当质量通过。先沿用现役预算和配置，不新增逐篇强制模型调用、专用 NLI 服务或全库评分系统。

四项是核查关注点，不另建评分或报告体系：有据/保真映射现有 D_fidelity，完整映射 B_completeness，取材可用性结合 A_synthesis/C_fluency；E_compliance 的格式与元数据契约继续保留。语义支持不要求逐字相同，精确原话才做逐字定位。

- 独立审者对照同版完整源和稿，不能只看作者的清单；长源分块时查跨段关系，局部未找到须回查邻文/其他块，不立刻判编造。只审了部分时记 partial/needs_review。
- 对每项问题保留稿片段、源位置与证据、问题类型、严重度和最小修订建议，复用现有报告字段；先核实真错/误报，再定向修订，并按现役重审协议复核新版本。修稿不借机添加外部分析。
- 正文/表格/标题/速览/图表中的明确无源新增、错主体、错指标、否定/因果/时序翻转、重大条件丢失，建议按现有 P1 口径处理；源支持但妨碍取材的重复、悬空指代和组织问题通常进入 P2，若改变含义则按影响升级。细则需与现役 rubric 一致，不能用高总分抵消严重失真。
- 机械门禁的现有硬拦继续有效；上述语义项不直接变成新的正则硬拦。异步复核仍是抽样结论，不能推为逐篇认证；显式开启保存前全文审核时，失败/未完成仍按既有准入处理，不另造豁免。
- 入队、发包、作者自检都不算独立审过；必须实际回收并校验版本。无人/无会话模型在环时保留待审，不能写成后台已自动完成。
- 审核本身也要校准：在现有评估目录选少量已裁定的错归属、漏条件、否定翻转等样本，配上含义正确但顺序/措辞改变的负样本，检查能否报出具体错误且不误杀重组。复用 S5/S8 有界预算，不新增常驻评测；构造错误样本和离线字段测试只能证明对应边界，不能代替真实稿件的语义验收。

### 9.10 联网核验的补充依据（2026-10-27）

本次查原始论文，以下仅作为设计依据，不是本库效果数据，也不据此安装新模型或改生产：

- [ALCE（EMNLP 2023）](https://aclanthology.org/2023.emnlp-main.398/)将引用质量检查落到证据是否完整支持输出陈述、引用是否相关；借鉴为“找到相关片段”进一步核对“支持整条陈述”。
- [FRANK（NAACL 2021）](https://aclanthology.org/2021.naacl-main.383/)区分主体、关系、时间/情境、指代和跨句因果/时序错误；借鉴为同词同数仍需核对归属与关系。
- [QuestEval（EMNLP 2021）](https://aclanthology.org/2021.emnlp-main.529/)同时考虑输出受源支持与保留源的重要信息；借鉴为稿→源与源→稿双向核查，问答只作取材检查的一种方法。
- [长文事实一致性指标压力测试（ACL 2026）](https://aclanthology.org/2026.acl-long.1472/)在其长文基准中观察到短文指标对等义改写及信息密集陈述的不稳定性；支持保留具体问题证据和复核，不能外推本项目模型的错误率或声称所有指标无用。

研究及当前机制核对后，本轮建议集中改善证据支持、关系完整和片段可用性；不需要扩大九类模板体系或增加延伸内容。是否改善仍由 §9.5 的本库配对和真实复核验证。
