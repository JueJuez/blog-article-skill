## 1. 目标与边界

目标是让读者在不打开原文时，也能准确理解原文的重要观点、事实口径、流程、限制和资源，区分作者自述、推测与笔记者分析。保留现有结构化表达、学习练习与洞察能力，但不能为这些功能改变原意。

本计划由“抽查其它模板的总结与原文，并形成提质开发计划”的请求产生。实施任务与验收在本文维护，不另建同义长期计划。模板清单以 `prompts/templates.py:NOTE_TEMPLATES` 为准，类型选择以 `prompts/classify.py` 为准。

原抽检只用于问题诊断；实施后的校准证据与验收边界见§8。全文文字对照不核实作者经营、投资、政策或科学观点的外部真实性。未读取视频画面、原著全书、网页图片和附件正文，不能把文字源未给信息说成这些媒介也没有。

不默认全库重写，不改写作台项目，不更换模型或接入外部服务，不扩大付费事实查证范围。未来发现缺源，沿 [PIPELINES](../PIPELINES.md) 的补源入口办理，不手写抓取接口。

## 2. 抽检方法与证据

登记标签覆盖情况：structured、case、dissection、interview、key_points、opinion、reading、roundup各2组，general为此前已对照的1组。这是**登记类型覆盖**，不是每类都有两篇语义适配的有效样本。特别是：一个访谈样本实际是模拟对话教学；一个 reading 样本实际是单集学习课；两个 roundup 样本均不是以同条件产品横评为主。后者可验证错配危害，不能替代真正横评的生成验收。

## 3. 当前实现与结构性根因

### 3.1 已有防线

当前共享规则已禁止编造、要求来源绑定/数字口径/推广标注和推断标签；case profile已有证据强度要求；机械门禁已有结构、锚点召回、重合和形态检查。不是所有历史错误都缺规则；部分需要验证现规则执行情况。

源码位置：`prompts/templates.py`的 `COVERAGE_FIRST_RULES`、`QUALITY_DISCIPLINE_RULES`、`UNIVERSAL_RULES`、`THINKING_LENS`、`QUALITY_GATE_SELFCHECK`；`prompts/verifier.py:verify_note_mechanical`；`prompts/review_rubric.py:DIMENSIONS`。

### 3.2 仍可确认的缺口

以下是实施前的诊断快照：第1、2项已在批次1修改契约与结构门禁，并完成有限校准；不再作为未动工事项。第3、6项已在批次2实现确定性分类与过程追踪并复跑已知反例；分类语义校准仍有限，第4项已由批次3补范围证据检查，但语义关系及第5项全文审核仍待批次4处理，实际进度以§8、§9为准。

1. **优先级与内容角色不清。**断言式因果标题、默认“原文事实”、去转述引导语，与作者立场/不确定性要求冲突。source事实在这里仅指源陈述，不等于外部核实过。
2. **固定模块制造强填压力。**正反例、全书地图、胜出选型、创作模具与新增类比在某些源中不存在；机械结构要求却仍以出现某些模块为准。缺模块不应驱动编内容。
3. **分类证据过弱。**标题+前800字符孤词及前2500字符二人称探针，可把否定语境“抄作业”、推广“读书”、模拟对话误判。必须区分内容主线与局部提到的词。
4. **质量检查无法核对语义关系。**数字/术语出现，不证明对象、期间、假设属性或时序正确。G01当前内容检查锚点召回87.5%、必备结构无缺项，仍有关键失真。提高召回阈值不能解决这个盲区。
5. **独立审核没有全文覆盖。**`templates.verify_note`截原文前6000字符；`articles/main.py`调用侧亦截6000，`videos/main.py`用节选再截6000。G01/U2重要限制在后半段。无外部AI的会话路径主要依赖自检与父Agent抽检，不能称每篇独立复核。
6. **版本与过程缺记录。**现有登记标签/时间不能稳定证明实际prompt/源版本。`filter_pending.refresh_prompt`刷新正文，沿用旧note_type；更新prompt不等于修复历史误路由。

### 3.3 根因链与防复发

为什么失真？归纳、对照和洞察新增了更强含义。为什么会新增？模板追求确定性和完整骨架。为什么没被前置约束消除？规则冲突且类型适配缺证据。为什么落盘前没有拦住？机械检查不懂关系、独立审核节选/未逐篇执行。为什么无法从历史迅速归因？缺实际prompt与源版本及审核覆盖信息。

这是系统性缺口，计划必须包含代码护栏和真实语义回归；仅修改禁令文字、记录经验或逐篇修旧文，不足以宣告修复。

## 4. 目标内容契约

### 4.1 共享优先级

推荐统一为：**忠实于已提供源及访问范围 → 核心信息与条件完整 → 对应内容的结构表达 → 可选学习/分析 → 文风与篇幅提示**。

- 源陈述按角色处理：亲历自述、观点、预测、举例/假设、引用他人、推广、笔记者分析；不能统称已证实事实。
- 速览、标题、公式、表格、图表与收束，保留正文同等的条件和不确定性；正文有风险，不代表首屏可以承诺最优或稳定赚钱。
- 因果、时间先后、人物归属、数字对象/期间/单位/分母/基线必须保持；源未给口径，明确未提供，不能补算净利或成功率。
- 原话只保可定位原句。转述和删节标明属性；ASR不能确定的数字、人名、术语保留疑点，不能靠听起来专业补全。
- 核心重要要点逐条对应，但允许有逻辑地重组；不要把“一一对应”硬等同于小节数量，不恢复字数比例硬门禁。
- 洞察、反方、类比与学习答案就近标笔记者分析；引用存在只证明素材来源，推导是否成立仍须检查。未经核验的外部事实不能靠【补充】获得可信性。
- 资源记录名称、用途、准确入口及读取状态。仅有附件名，写“原文附件，正文未读取”；正文截断也明确标范围，不声称完整实操。

### 4.2 各模板调整

| 类型 | 应保留的主产物 | 需调整的结构与约束 |
|---|---|---|
| structured | 定义、机制/流程、关键条件与案例 | 公式和正反例按源出现；例子只有一面时保原面，额外分析另区；建议与条件不能压成绝对对错 |
| general | 按源主线整理的重要内容 | 虽共享structured实现，也必须允许非教程型源，不能兜底后强造方法论/公式 |
| key_points | 主论点、论据、讲话与点评 | 金句绑定说话者及原句；行动项不能把点评者推测变亲历成功机制 |
| case | 背景、动作、结果、失败、约束 | 事件按真实时间/因果；流水/营收/GMV/收益/净利分清；单案例归因保留替代因素 |
| opinion | 作者立场、前提、论据及源中的反驳 | 原文没正反辩论时不强造；最强反驳可作为明确分析，不能并入作者立场；保假设属性 |
| interview | 真实说话者关系、问题与回答、叙事转折 | 模拟情景不当真实访谈；不知道说话者就标不明，不造嘉宾/共识/提问 |
| roundup | 同条件对象×维度比较、条件化选择 | 缺同条件证据不排名；条件不同分表或注明不可比；局部比较不吞掉全文复盘主线 |
| reading | 所读材料的论点、论据与范围 | 原著/书评/单集解说分清；全书地图仅全文足够时写；账号、UP主、译者与书作者不可互替；外部争议不脑补 |
| dissection | 各案例的结构与运营机制 | 标题/钩子/节奏/CTA有源才提炼；运营动作独列；跨案例综合模具标分析与适用条件，不能作单视频已验证结构 |
