# PRD · blog-article-skill 开发需求文档

> 版本：v1.0　|　更新：2026-07-19　|　维护：项目内直接维护（不额外注册用户级技能）

---

## 1. 背景与目标

`blog-article-skill` 是一个"内容 → 结构化笔记"的本地技能，把文章 / 视频的原文或字幕，按内容类型套用对应笔记模板，生成干净 Markdown 笔记并落库（本地 / Obsidian / 飞书）。

当前已具备三模块架构：

- `articles/`：文章博客模块（抓 URL → AI 总结 → 多目标保存），已可用。
- `prompts/`：共享笔记模板模块（按内容类型切换的 Prompt 注册表 + 分类器）。
- `videos/`：视频模块（脚手架，复用 `articles` 的总结与保存能力）。

**目标**：在不破坏现有总结能力的前提下，补齐 articles 的外围增强、把 videos 从"字幕粘贴"推进到"自动抓取 + 超长/分集可用"，并明确"自建薄封装、不 fork 整站"的架构路线。

---

## 2. 架构原则（硬约束）

1. **获取层与总结层解耦**：字幕/转写获取（获取层）与 AI 总结（总结层）分离，互不影响。
2. **长度不进总结，先切后总**：任意长度 transcript 先经过"预处理/分块"再喂给模板，绝不因超长爆上下文。
3. **WorkBuddy 内置 AI 为可选增强，绝不阻断主流程**：有就用、没有就跳过，原降级行为（返回 prompt+正文手总结）保持不变。用户在 Trae / CLI / 其他 AI 平台运行时流程不受影响。
4. **不 fork 整个视频总结 Web 应用**：自建薄封装，用成熟 OSS 库（`youtube-transcript-api` / `yt-dlp` / `faster-whisper`）作依赖，解决"拿字幕"这一个问题。
5. **中国短视频平台（抖音/快手/视频号/小红书）反爬严重**：链接直抓不稳，现实路径是"本地文件 → ASR"兜底，不在 P2 承诺链接直抓。

## 5. 关键场景与预期行为

| 场景 | 输入 | 预期 |
|---|---|---|
| 普通文章 | URL | A1 升级后干净正文 → 自动分类 → 对应模板笔记 → 落库 |
| 短视频（有字幕） | YouTube Shorts / B站短视频 URL | P2.1 拿字幕 → `key_points` 笔记 |
| 短视频（无字幕，中国平台） | 本地视频文件 | P3（ASR）或用户本地存文件后走 ASR 兜底 |
| 8h / 24h 长视频 | URL（有 CC/章节） | P2.2 按章节切 → 逐章小结 → 合并总览，不爆上下文 |
| 24h 无字幕视频 | URL | 劝用户先裁片段或提供 CC；不硬跑本地 ASR |
| 连续剧 / 合集 | playlist URL | P2.3 自动下一P，每集单独成篇 + 合集总览（叙事类或需 recap 模板，后加） |

---

## 6. 不在范围内（Out of Scope）

- **fork 整个视频总结 Web 应用**（UI/数据库/登录/部署）：与本技能"落 .md 到 Obsidian"的单向管道设计冲突，维护成本高。
- 多端同步 / 社交 / 搜索等**产品壳**：属独立产品方向，非本技能范畴。
- 直播实时字幕总结。
- 抖音/快手/视频号**链接直抓**（反爬不稳，仅本地文件兜底）。

---

## 7. 里程碑建议

1. **M1（先打）**：P2（字幕自动抓 + 分块 + 分集）+ C1 预处理模块 —— videos 从"能用"到"真正好用"的关键一步。
2. **M2**：Articles 并行增强 A1–A6 + C2 —— 外围打磨，互不阻塞。
3. **M3**：P3 本地 ASR 转写 —— 覆盖无字幕/本地文件。
4. **M4（可选）**：P4 多模态理解 —— 锦上添花，不挡主线。

---

## 8. 风险与边界

- **中国短视频平台链接直抓**：yt-dlp extractor 常失效，靠本地文件兜底，不在 P2 承诺。
- **24h 本地 ASR**：CPU 上按天计，不现实；超长视频优先 CC 或先裁片。
- **超长无章节视频**：靠分块两段式，质量略低于"有章节"情况。
- **连续剧叙事类**：需 recap 型模板（注册表后加，不挡 P2）。
- **外网出口**：P2/P3 的 `yt-dlp` 需能访问外网，沙箱内可能需放到沙箱外或本地执行。
- **模型下载**：P3 `faster-whisper` 首次下载模型（~150MB–1.5GB）。
