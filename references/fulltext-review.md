# 全文语义审核与失败闭环

对应模板质量计划批次4；复用现有文章、视频、队列、原路径重做与系列维护入口，不另建保存链路。

## 默认与准入

- `NOTE_QUALITY_GATE=0`保持默认：无新增外部审核调用，记录`not_performed/none`；自检和现有抽检继续执行，不认证独立全文通过。
- 显式开启后，缺源、明确截断、超时、无模型、mock、坏JSON、部分覆盖、未解决关系均阻止保存。`force`不豁免。重大失真不能靠高分抵消。
- 原始候选加最多两次内容修订；每次修后用完整源重新审核。技术失败不靠重生成碰运气。审核后的源、稿、type或prompt版本改变会要求重审。
- 保存准入在输出管理器、覆盖和最终格式化之前；失败的源、候选、报告和修订审核历史随现有`_review_queue.jsonl`与`gate_blockers`台账保留，原队列不出队，旧好稿不覆盖。台账写入失败的可用性限制沿用既有实现；不能把异常记成保存成功。
- draft-only保存审核正文、源、版本及格式化文件hash；Landing在输出前再次检查它们。显式开启审核时，旧无版本草稿或已被修改的文件保留待复核；默认关闭的旧草稿仍沿用原流程。

## 全文送审与证据

`prompts/semantic_review.py`按10000字符主块、两端600字符邻文拆分，长单行同样完整覆盖。源块×稿块全部送审，避免长稿尾部也漏掉；多块后附完整块报告做关系汇总。局部找不到不直接等同编造，待核关系进入claims，汇总后仍未解决则needs_review。确定的P1或明确失败不能被汇总高分洗掉。

每候选最多64次审核调用（含汇总），汇总载荷超过120000字符则停止并记未完成；应缩小批量/人工复核，不截源或截报告。调用使用原provider与其超时/退避，不新建服务或替换模型。报告记录调用数、实际载荷hash、范围、结果、可获得的usage/model/provider和耗时；未暴露字段写unknown/not_exposed，不估算成真实费用。

源/稿SHA256使用实际UTF-8文本；派单prompt和审核prompt分别绑定。视频的生成prompt指逐次调用hash清单的hash，清单保留每次prompt/input hash，不冒充单一基础模板。正文hash范围为主题词提取后的模型正文，**不是**最终追加标签、元数据和来源链接后的文件。

coverage=full仅证明所有指定字符范围送入审核并收到有效返回；不证明模型逐字理解或AI零误差。reviewer记录独立审核调用角色，不保证不同模型家族。缺源/附件未读不能认证访问了外部媒体；外部事实真实性仍不在此次范围。

## 会话独立审核协议

`FORCE_AGENT_MODE`下作者读派单prompt与全源写稿，自检不当独立审核。由另一位会话审者对照同一版本**完整源与完整稿**，按五维rubric做双向覆盖、人物/时序/数值口径/假设、首屏强度、分析标签和访问范围核对。另固定两项观察（不计入五维总分，作为P1/P2问题上报）：**机制链完整性**（资金/流程/因果是否有一句完整文字链路，不只端点、不只图）与**数字归属**（表格/结果表数字是否挂在源里对应主体/讲者名下；挂错人按P1，哪怕数字本身在源里存在）。每个问题保留稿片段与行范围、源片段与行范围、严重度P1/P2、理由和修订建议。只能看到一部分时必须记partial/needs_review。

报告由编排方核验审者身份与访问范围后提交。ID是本地声明记录，不是平台签名认证；不能靠改字段把作者冒充另一会话。尚未核验或无法证明实际派单版本时保留unknown，不补历史证据。

JSON字段示意（hash和长度必须实际计算，不能照抄占位符）：

```json
{
  "version": "fulltext-v1",
  "source_sha256": "实际源hash",
  "note_sha256": "去主题词后的实际正文hash",
  "generation_prompt_sha256": "派单generation_context.prompt_sha256",
  "prompt_sha256": "QUALITY_GATE_PROMPT的实际hash",
  "note_type": "general",
  "reviewer": {"role": "independent_session", "id": "实际审者ID", "author_id": "实际作者ID"},
  "ranges": [{"source": [0, 12345], "note": [0, 2345]}],
  "coverage": "full",
  "status": "passed",
  "passed": true,
  "score": 95,
  "issues": [],
  "findings": []
}
```

range为零基字符半开区间；必须与完整文本长度一致。任何未解决问题应passed=false；P1不得通过。作者与审者相同、unknown版本、陈旧源/稿/prompt、部分范围不能通过。

- 队列：`python scripts/save_pending.py --queue monitors|scys --key <key> --file <稿.md> --review-file <报告.json>`。只带报告不强制打开外部模型开关；失败报告同样阻止写入。
- 原路径重做：稿旁`<稿.md>.review.json`，或批次条目显式`review_file`；保留既有源路径、原路径覆盖与版本校验。
- 无报告的普通队列不增加调用。高风险优先派独立审者，没审仍记未审，批次3的机械supported/observed不得升级为语义通过。具体问题最多修两次，报告须针对新稿重出；仍失败保留待办，不自动force。

## 验收边界

脱敏fixture和模拟provider仅验证调度、绑定、重试与准入；真实源只读输送诊断仅证明原文后半段实际进入载荷。模型识别失真能力、人工标注、留出效果和真实费用需要单列校准；均不能用pytest通过替代。
